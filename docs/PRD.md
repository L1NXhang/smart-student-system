## 1. 项目概述

### 1.1 项目背景

为深入学习贯彻习近平新时代中国特色社会主义思想，全面落实国家教育数字化战略部署，学校决定举办"智慧学工系统"设计大赛。本项目旨在开发一款集学生信息管理、日常事务办理、学业发展支持于一体的综合性智慧学工信息系统。

### 1.2 项目目标

| 目标 | 描述 |
|------|------|
| **功能完整性** | 完整实现六大核心功能模块，确保系统实用性 |
| **交互便捷性** | 简洁美观的 UI 设计，精致细腻的交互动效 |
| **技术创新性** | 采用现代化技术栈，实现高效、安全的系统架构 |
| **实际应用价值** | 真正解决学工管理痛点，提升管理效率 |

### 1.3 目标用户

| 用户角色 | 权限范围 | 主要功能 |
|----------|----------|----------|
| **学生** | 查看个人信息、提交申请、查看通知等 | 信息查看、申请提交、消息接收、活动报名 |
| **教师/管理员** | 管理学生信息、审核申请、发布通知等 | 数据管理、审批流程、信息发布、系统配置 |

### 1.4 系统形式

- **平台类型**：Web 网站
- **访问方式**：浏览器访问，支持 PC 端和移动端响应式适配
- **部署方式**：自有服务器部署

## 2. 功能需求

### 2.1 用户认证模块

#### 2.1.1 功能描述

实现教师、学生两类用户身份的注册、登录及权限差异化使用功能。

#### 2.1.2 功能列表

| 功能 | 学生 | 管理员 |
|------|------|--------|
| 登录 | ✓ | ✓ |
| 注册 | ✓（需审核） | ✓（系统预设） |
| 修改密码 | ✓ | ✓ |
| 退出登录 | ✓ | ✓ |
| 权限控制 | 学生权限 | 管理员权限 |

#### 2.1.3 业务规则

1. 学生注册需填写学号、姓名、联系方式等基本信息，提交后由管理员审核
2. 管理员账号由系统预设，不支持自主注册
3. 登录采用账号+密码方式，支持记住登录状态
4. 不同角色登录后跳转至对应权限的首页

### 2.2 模块一：学生基本信息管理

#### 2.2.1 功能描述

涵盖学生个人信息的录入、查询、修改与维护功能，实现学生信息"一站式"整合管理。**需实现单页面完整展示**。

#### 2.2.2 信息字段清单

**基础信息区**
| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| 姓名 | 文本 | ✓ | 学生姓名 |
| 学号 | 文本 | ✓ | 唯一标识 |
| 照片 | 图片 | ✓ | 证件照 |
| 联系方式 | 文本 | ✓ | 手机号码 |
| 身份证号码 | 文本 | ✓ | 18位身份证号 |

**学籍信息区**
| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| 学院 | 选择 | ✓ | 所属学院 |
| 专业 | 选择 | ✓ | 所属专业 |
| 年级班级 | 选择 | ✓ | 年级+班级 |
| 校区 | 选择 | ✓ | 所在校区 |
| 宿舍号 | 文本 | - | 校内住宿 |
| 非集中住宿地址 | 文本 | - | 校外住宿地址 |

**个人特质区**
| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| 病史 | 文本 | - | 既往病史 |
| 爱好 | 文本 | - | 个人爱好 |
| 性格特征 | 文本 | - | 性格描述 |
| 职业目标 | 文本 | - | 职业规划 |

**联系信息区**
| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| 班主任 | 文本 | ✓ | 班主任姓名 |
| 班主任联系方式 | 文本 | ✓ | 班主任电话 |
| 父亲姓名 | 文本 | - | - |
| 父亲联系方式 | 文本 | - | - |
| 母亲姓名 | 文本 | - | - |
| 母亲联系方式 | 文本 | - | - |
| 紧急联系人1 | 文本 | ✓ | 姓名+关系+电话 |
| 紧急联系人2 | 文本 | ✓ | 姓名+关系+电话 |

**特殊信息区**
| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| 困难认定等级 | 选择 | - | 一般困难/比较困难/特别困难 |
| 特殊人员证明材料 | 文件 | - | 图片/PDF上传 |

#### 2.2.3 功能操作

| 功能 | 角色 | 说明 |
|------|------|------|
| 信息录入 | 管理员 | 新生信息录入 |
| 信息查询 | 学生/管理员 | 学生查看本人信息，管理员查看所有 |
| 信息修改 | 学生 | 提交变更申请 |
| 信息导出 | 学生/管理员 | 仅管理员和本人可导出 |

#### 2.2.4 业务流程

**信息变更申请流程**
```
学生提交变更申请 → 管理员审核 → 审核通过 → 信息更新生效
                           → 审核拒绝 → 驳回原因反馈
```

**困难认定申请流程**
```
学生提交困难认定申请 → 上传证明材料 → 管理员审核 → 认定等级 → 记录生效
```


### 2.7 模块六：沟通互动

#### 2.7.1 功能描述

#### 2.7.2 班主任与学生实时聊天

**功能形式**：实时聊天（基于 WebSocket，类微信/QQ 体验）

**技术方案**：Socket.io 实现实时双向通信

**聊天功能**
| 功能 | 说明 |
|------|------|
| 实时消息 | 消息即时发送与接收，无需刷新页面 |
| 消息历史 | 自动加载历史聊天记录，支持分页 |
| 正在输入提示 | 显示"对方正在输入..."状态 |
| 未读消息数 | 侧边栏显示未读消息红点 |
| 在线/离线状态 | 显示联系人在线状态 |
| 消息类型 | 支持文本消息 |

**聊天界面布局**
```
┌──────────────────────────────────────────────┐
│              班主任与学生聊天                    │
├────────────┬─────────────────────────────────┤
│            │         聊天对象：张老师          │
│  联系人列表 │  ─────────────────────────────  │
│            │                                 │
│  🔴 张老师  │  [张老师 10:30]                 │
│  🟢 李老师  │  你好，请问奖学金什么时候开始申请？│
│            │                                 │
│            │  [我 10:31]                     │
│            │  你好！下周一正式开始，注意关注通知。│
│            │                                 │
│            │  ─────────────────────────────  │
│            │  [对方正在输入...]               │
│            │  ┌─────────────────┐ [发送]     │
│            │  │ 输入消息...      │            │
│            │  └─────────────────┘            │
└────────────┴─────────────────────────────────┘
```

**通信流程**
```
客户端 A（学生）                服务端                   客户端 B（班主任）
     │                          │                          │
     │── socket.connect() ────→ │                          │
     │                          │←── socket.connect() ────│
     │                          │                          │
     │── emit('chat:message') ─→│                          │
     │                          │── emit('chat:message') ─→│
     │                          │                          │
     │                          │←── emit('typing') ──────│
     │←── emit('typing') ──────│                          │
     │                          │                          │
     │←── emit('online') ──────│←── emit('online') ───────│
```

**消息存储**
- 所有消息实时写入数据库，保证消息不丢失
- 用户上线时自动拉取离线消息
- 历史消息分页加载（每次 20 条）

## 3. 非功能需求

### 3.1 性能要求

| 指标 | 要求 |
|------|------|
| 页面加载时间 | < 3 秒 |
| 接口响应时间 | < 1 秒 |
| 并发用户数 | 支持 100+ 并发 |
| 数据导入速度 | 1000 条/分钟 |

### 3.2 安全要求

| 要求 | 说明 |
|------|------|
| 身份认证 | 登录验证，Token 机制 |
| 权限控制 | 基于角色的访问控制（RBAC） |
| 数据加密 | 密码加密存储 |
| 操作日志 | 关键操作记录日志 |
| XSS 防护 | 输入过滤，输出转义 |

| 类型 | 要求 |
|------|------|

| 分辨率 | 响应式设计，支持 1366x768 及以上 |

### 3.4 可维护性

- 代码规范统一
- 注释完善
- 模块化设计
- 配置与代码分离

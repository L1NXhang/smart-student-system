# 中国大学生计算机设计大赛 — 参赛说明

## 赛道选择

**选择大类**：软件应用与开发

**选择小类**：Web 应用与开发

## 赛道选择原因

在学校日常生活中，学生与辅导员联系、部门发布活动、奖学金申请、安全报备等功能分散在多个平台，导致师生需要在不同软件之间频繁切换，操作繁琐，效率低下。现有平台普遍存在以下痛点：

1. 功能割裂：学生事务管理涉及信息查询、奖助申请、学业发展、安全管理、沟通互动等多个方面，但每个方面都有独立的系统或渠道，缺少统一入口。
2. 交互体验差：多数现有系统界面陈旧，移动端适配不足，操作路径长，学习成本高。
3. 响应速度慢：部分系统技术架构老化，页面加载缓慢，影响日常使用体验。

基于以上痛点，我们决定开发一套**响应更快、UI更精美、适配更好**的智慧学工系统，将学生事务管理的全部核心功能聚合于一体平台，提供 PC 端和移动端双端一致的高质量体验。本项目采用现代 Web 技术栈（Vue 3 + Node.js + MySQL），实现前后端分离架构，并深度应用 GSAP 动画库提升交互品质，充分契合"Web 应用与开发"赛道的技术要求。

同时，信息管理系统也是智慧学工系统的本质属性——本系统完整实现了学生基本信息管理、奖助服务管理、学业发展支持、职业规划、安全管理与预警、沟通互动等六大核心模块，涵盖了信息的录入、查询、修改、审核、统计、导出等全生命周期管理功能，与"信息管理"小类同样高度契合。综合考量技术实现与用户体验的双重侧重，我们最终选择 **Web 应用与开发** 作为参赛小类。

## 前期准备工作

### 一、技术准备

在项目启动前，系统性地学习了以下关键技术：

- **前端技术**：Vue 3 Composition API、Vite 构建工具、Element Plus 组件库、GSAP 动画引擎、Pinia 状态管理、Vue Router 路由管理、Axios HTTP 请求库
- **后端技术**：Node.js 运行时、Express.js Web 框架、Sequelize ORM、MySQL 关系型数据库、JWT 认证机制、Socket.io 实时通信
- **部署技术**：Docker 容器化、Nginx 反向代理与静态资源托管、云服务器运维、SSH 远程管理
- **工程化**：Git 版本控制、前后端联调与接口规范、响应式移动端适配

### 二、工具准备

准备了以下开发与部署工具：

- **轻量级应用服务器**：腾讯云轻量应用服务器（Ubuntu 22.04, 3.6GB RAM, 40GB SSD），用于系统部署与公网访问
- **AI 辅助开发工具**：Claude Code（AI 编程助手），用于加速代码编写、Bug 修复、架构设计等开发环节
- **DeepSeek V4 Pro API Token**：提供额外的 AI 能力支持
- **智能体（OpenClaw AI Agent）**：部署于服务器的 AI 助手，辅助日常运维与测试

### 三、协作准备

- **GitHub 项目协作**：使用 Git 进行版本控制，GitHub 作为远程代码仓库，规范化 Commit 格式（`[Frontend]` / `[Backend]` / `[Feature]` / `[Fix]` / `[UI]` / `[Project]`），确保开发过程可追溯、可协作
- **前后端分离协作**：明确 API 接口规范，前后端独立开发与联调

### 四、素材与参考

- **校徽素材**：参考并使用西华师范大学校徽作为系统品牌标识
- **成熟案例参考**：研究易班智慧学工平台等成熟案例的功能设计与交互模式
- **核心功能模块**：通过团队讨论，对照大赛要求确定了六大核心功能模块的设计方案
- **技术文档**：查阅 Vue 3、Element Plus、GSAP、Express、Sequelize 等官方文档与社区资源
